> Designer playtest verdict: "rain visuals look really bad… god rays
> are not visible… needs hours of player iteration and VFX and SFX
> work on another day." Phases A (rain shader), B (wet terrain +
> splashes), and D (god rays) are gated behind GraphicsManager toggles
> defaulting OFF. Phase C (audio envelope) is live as an objective

>

> + LIGHT SHAFTS in F1 → GRAPHICS / POST-FX to bring the systems back

Scope: address the four "Weather rework" items deferred from PR #244
(see `DESIGNER_TODO.md` Section 9 → "Weather rework").

## Acceptance criteria (designer-stated)

- **Rain visual.** Must build up over the transition, not snap. Must be
  visible regardless of camera angle (looking up / down / level). The
  current `GPUParticles3D` billboard streaks read as on/off even with
  density modulation — the user wants a deeper redesign.
- **Rain audio.** Must NOT lag the visual onset (current setup has a ~5
  s gap). Crossfade must feel like a build-up, not a perceptual switch.
- **God rays.** Must be visibly present when CLEAR and visibly absent
  during HEAVY_RAIN. Currently imperceptible at any
  `light_volumetric_fog_energy` multiplier.
- **Rainbow.** Must be visible in the sky after a heavy-rain → clear
  transition. State machine works; shader output is invisible.

## Approach per item

### A. Screen-space rain shader

Replace the 3D `GPUParticles3D` rain rig with a **full-screen
`canvas_item` rain shader** living on the existing `RainOverlay`
CanvasLayer.

- Two procedural streak layers at different parallax depths (no
  texture asset dependency to start — both layers generated by
  hashing screen UV into streaks). Closer layer = bigger / faster /
  fewer; farther = smaller / slower / denser.
- Streak length, density, and alpha all drive off a single
  `rain_density` uniform (pushed each frame from
  `WeatherManager._live_rain_density / _MAX_WETNESS_DENSITY`).
- Slant from `wind_direction` projected to screen-X: pushed as a
  scalar `rain_slant` each frame.
- View-angle parallax: shift each layer's UV by camera pitch so the
  rain feels "ahead of" the camera when looking down.
- Disable when player is underwater (subscribe to UnderwaterFilter
  state or check `WaterFlowManager.is_position_in_water` on the
  camera once per tick).
- Keep `_build_rain_particles` rig as a fallback toggle via
  `GraphicsManager` (`rain_3d_fallback_enabled`, defaults OFF) so
  the old look can be A/B'd if the new one regresses something.
- The existing blue-grey `RainOverlay.TintRect` colour mood stays
  (multiplied with shader output via blend order: shader on top,
  tint underneath).

### B. Wet-surface terrain mod + splash particles

- New global shader parameter `wetness_factor` (0..1) pushed each
  frame from `_live_wetness`. `terrain_voxel.gdshader` samples it
  to lower `surface_roughness` (0.9 dry → 0.3 wet) and slightly
  darken albedo (×0.85 at full wet). Existing `_wet_terrain_visual`
  StandardMaterial path (which crashed on `VoxelLodTerrain` because
  it's not a `GeometryInstance3D`) gets retired in favour of this.
- Small splash GPUParticles3D under the player — short-lived flat
  rings that fade in on rain density. ~80 particles, fixed AABB,
  cheap.

### C. Audio crossfade envelope rework

- New `WeatherEnvelopeProfile` Resource (`scripts/WeatherEnvelopeProfile.gd`)
  holds: `lead_seconds` (delay before fade starts — 0.0 default to
  match visual onset), `fade_seconds` (length of the actual ramp —
  was 5.0), `curve_pow` (the exponent applied to amplitude `t`
  before back-converting to dB — 2.2 default, makes the perceived
  loudness feel linear), `lowpass_open_hz_from` / `lowpass_open_hz_to`
  (a low-pass cutoff that opens as level rises so the bed
  "approaches" rather than appears — a per-bus AudioEffectFilter).
- `_swap_ambient_audio` rebuilt around the envelope profile:
  `Tween.tween_method` on a 0..1 progress driver that calls
  `_apply_envelope_step(player, profile, progress)` each tick,
  which writes both `volume_db` (from amplitude curve) and the
  low-pass cutoff (lerped).
- The 5 s lag the designer reported is killed by removing the
  `AMBIENT_CROSSFADE_S = 5.0` floor that ran the *outgoing*
  player's full fade-out before the *incoming* one ramped — the
  two now run concurrently with a fresh envelope each.

### D. God rays via WorldEnvironment.volumetric_fog co-tune

- `WeatherManager.STATE_PROFILES` gain three new keys per state:
  `volumetric_fog_density`, `volumetric_fog_length`,
  `volumetric_fog_albedo` (Color). Interpolated alongside the
  existing `_live_*` values.
- New `_apply_god_rays_to_env` pushes those three (plus the
  existing `god_ray_multiplier` → `Sun.light_volumetric_fog_energy`)
  to the `WorldEnvironment.environment` each tick.
- CLEAR profile gets the underwater volumetric reference values
  scaled for above-water (sparse fog, high light energy multiplier
  so the rays read against any backdrop). HEAVY_RAIN gets 0 so the
  sun is fully occluded.
- UnderwaterFilter's submerge override must still win — preserve
  the snapshot/restore pattern.

### E. Rainbow debug + visibility fix

- Add a debug shader mode (`rainbow_debug = 1` uniform) that
  renders `rainbow_factor` as a fullscreen tint — confirms the
  global param is reaching the sky pass.
- Verify the antisolar-point projection: print
  `dot(EYEDIR, -LIGHT0_DIRECTION)` from a probe; rainbow draws
  where dot ≈ cos(40°) ≈ 0.766, which means the user must be
  looking *away from* the sun. After a heavy rain at 8 AM the
  sun is east; the rainbow is west, but if the test camera is
  facing east (toward the sun) it will be off-screen — this is a
  designer-positioning issue we can sidestep by bumping
  `rainbow_band_strength` so it shows up at a wider angular
  range, and/or adding a `RainbowDebug.gd` autoload helper that
  rotates the player camera to face the antisolar point when
  `F12+R` is pressed during a rainbow window.
- Crank `rainbow_band_strength` default from 1.5 to 3.0 and check
  for `night_factor` crushing — clamp the rainbow contribution
  with `max(day, 0.4)` so it isn't fully zeroed at dusk.

## Implementation order

A → C → D → B → E. A and C are the headline designer asks; D and B
are co-tunes; E is a small debug session that goes last because the
shader compile cycle is faster once everything else is in place.

## Rollback table

Each phase is one commit. If any phase regresses the designer
experience, `git revert <sha>` it. The audio crossfade rework needs
extra care because it changes `_swap_ambient_audio` signature.

## Not in scope

  designer complaint surfaces).
- Lightning visuals (working).
- Cloud system (working — fixed in PR #244 cloud_phase accumulator).
