2026-04-29 | Dialogic dialogue box overflows 320x180 viewport | Default Dialogic style is sized for 1080p. In Dialogic → Styles, set box width ~280px, height ~60-70px, anchored bottom-center. Font size 6-8px (renders crisp at 4x scale). Configure via editor only — not a code fix. | —
2026-04-30 | `move_toward(Vector2.ZERO, SPEED)` causes instant stop | Step arg is per-call, not per-second. Player hit zero velocity in one frame. Add a `DECEL` constant and multiply by `delta` so braking is frame-rate independent. | #34
2026-04-30 | ColorRect (Control node) drifts from world-space siblings | Control nodes anchor to screen/viewport space. When Camera2D moves, a ColorRect placed under Node2D shifts visually while Node2D siblings stay fixed. Use Polygon2D or Sprite2D (Node2D subclasses) for world-space placeholder visuals. | #34
2026-04-30 | PointLight2D light bleeds through walls | `CollisionShape2D` blocks physics but NOT light. Add `LightOccluder2D` + `OccluderPolygon2D` to walls so 2D light is contained. | #36
2026-04-30 | Radial light origin offset by ~128px (light "from outside" the campfire) | `GradientTexture2D` `fill_from` defaults to `(0,0)` (top-left) — NOT center. With `fill = 1` (radial), the bright spot lands at the texture's top-left, not its middle. Always set `fill_from = Vector2(0.5, 0.5)` and `fill_to = Vector2(1, 0.5)` for centered radial gradients used as light textures. | #37
2026-04-30 | 2D→3D coordinate confusion: `Input.get_vector` returns Vector2(x, y) but in 3D, the floor is the **XZ plane** with Y as up. | Map `input_dir.x → velocity.x`, `input_dir.y → velocity.z`. Don't try to use `input_dir.y → velocity.y` — that would launch the player into the air. | M4-3D
2026-04-30 | Camera clipping through walls in 3D | Use `SpringArm3D` as the camera mount (not a bare Camera3D). `SpringArm3D` casts a sphere from the pivot toward the camera position and shortens the arm if anything blocks it — built-in wall avoidance, no script needed. | M4-3D
2026-04-30 | `PointLight2D.energy` flicker logic doesn't compile under `OmniLight3D` | The 3D property is `light_energy`, not `energy`. Math is identical, only the property name changes. | M4-3D
2026-04-30 | `CollisionShape3D` placed at the origin makes a CharacterBody3D's feet sink into the floor by half its height | A capsule shape's origin is its **center**. For a 1.7 m tall capsule, set the CollisionShape3D's local Y position to `+height/2` (e.g. 0.85) so the bottom of the capsule sits on Y=0. Same for the visual mesh. | M4-3D
2026-05-03 | `VoxelMesherCubes` showed untouched terrain even after edits drained successfully through `VoxelEditManager._apply_edit` | Cubes reads `VoxelBuffer.CHANNEL_COLOR`, not `CHANNEL_SDF`. Edits writing to SDF were correct on disk but invisible because the mesher never read them. Fix: `tool.channel = CHANNEL_COLOR`, `tool.mode = MODE_SET`, `tool.value = packed_rgba` (0 = alpha-zero = carved air). | #102
2026-05-03 | `VoxelGeneratorScript` produced "Central buffer must be valid" errors thousands of times at world load | The script must override `_get_used_channels_mask()` to declare which channels it writes (`return 1 << VoxelBuffer.CHANNEL_COLOR` for Cubes-mesher generators). Without it, Zylann assumes default-SDF and never allocates the channel the mesher actually reads. | M5-3D bring-up
2026-05-03 | `VoxelTool.do_sphere(world_pos, world_radius)` carved at 1/8 the size and 8× closer to origin than expected | The tool takes **voxel-grid coords**, not world. With `terrain.transform.scale = 0.125` (8 vox/m), pass coords through `terrain.to_local()` and multiply radii by `1.0 / scale.x` before calling `do_sphere` / `do_box`. | #103
2026-05-03 | `var x := arr[0]` fails parse with "Cannot infer type" | `Array` returns `Variant` for index access, and the walrus operator can't infer from `Variant`. Type-annotate explicitly: `var x: Node = arr[0]`. Same applies to `Dictionary` value access. | #102
2026-05-03 | `var basis: Basis = ...` triggers SHADOWED_VARIABLE_BASE_CLASS warning in any `Node3D` subclass | `Node3D.basis` is an inherited property. Rename local variables — `cam_basis`, `local_basis`, `body_basis`. | #102
2026-05-03 | `TransitionManager.go_back()` did nothing on first launch from `MainMenu` | `change_scene()` only pushed `GameState.current_scene` to history when non-empty, but on first run that field starts empty. Fall back to `get_tree().current_scene.scene_file_path` so the initial scene always lands in history. | #100
2026-05-03 | `Settings.tscn` sliders and buttons completely unresponsive | Dialogic's input subsystem consumes `InputEventMouseButton` events project-wide before Godot's `_gui_input` dispatcher fires. Three UIs already work around this with manual `_input` + `Rect2.has_point()` dispatchers (`MainMenu`, `PauseMenu`, now `Settings`). Standard `Button.pressed` / `HSlider` drag will not work in this project — implement manual hit detection. | #100
2026-05-03 | `Settings` mouse cursor invisible / clicks register at wrong screen position | `PauseMenu._close()` sets `Input.mouse_mode = MOUSE_MODE_CAPTURED` before transitioning to Settings. Any UI scene reached from PauseMenu must explicitly set `Input.mouse_mode = MOUSE_MODE_VISIBLE` in its `_ready()`. | #100
2026-05-03 | `PowderCharge` carved at 2 m radius even after `voxel_aoe_radius = 10.0` was set in `ITEM_REGISTRY` | `ThrowableHandler` instantiated the scene but never read inventory stats, so the spawned RigidBody3D kept its `@export` defaults. When data lives in a registry but is consumed by an instance, the registry-to-instance copy step is silent if missing — verify it explicitly. Pattern: after `instantiate()`, `for key in ITEM_REGISTRY[id]: if key in instance: instance.set(key, ...)`. | #105
2026-05-03 | Explosives "didn't detonate" — log showed BOOM but player saw nothing | Detonation had zero on-screen feedback; player read large invisible carve as "didn't work." Every gameplay event needs visual feedback before the carve/damage/etc. lands — light flash + emissive sphere with a tween-driven fade is enough as a placeholder until real VFX. | #106
2026-05-03 | Throwables flew flat-forward regardless of camera pitch | Spawn used `_player.transform.basis.z` (player body forward, horizontal-only) plus a hardcoded `+UP * 0.3` bias, so aiming up and aiming down produced the same throw. Read `-camera.global_transform.basis.z` for direction (carries pitch); spawn position can stay anchored to body forward at chest height so the charge doesn't materialize at Roland's feet when looking sharply down. | #108
2026-05-03 | Player walked on water plane / water plane buried under terrain | Logic was correct (`feet_y <= surface_y`); world geometry was wrong. Terrain biased `+10 m` for accessible spawn put average ground at Y=10 while ocean was at Y=0 — water plane invisible under terrain. Raise water elevation to match the biased terrain (Y=6 puts low ground in valleys underwater while flat ground stays dry). When swim physics "doesn't work," check world Y values before assuming a code bug. | #109
2026-05-03 | Saves loaded against a baseline-changed generator floated in mismatched terrain | Bumped `VoxelEditManager.WORLD_GENERATOR_VERSION` is non-negotiable for every shape-affecting change to `CubicHeightmapGenerator` (height range, offset, noise layers, quantization, color mode). `GameState.save_game` stamps the version; `load_game` refuses the load on mismatch. There is no silent migration. | M5-3D bring-up
2026-05-03 | Designer iteration loop on terrain look took ~10 min/iteration via PR-and-rebuild | Add `@tool` + `@export_range(min, max, step)` to expose every numeric knob as Inspector slider. Add a `Preset` enum with a setter that batch-writes a stored param dict — guard against re-entrance with a `_applying_preset: bool` flag, otherwise the inner `set()` calls re-fire the setter. Designer F5s once and tunes live; `git` is only invoked when baking a chosen preset. | #109
2026-05-03 | Carve sphere "stopped working" after 3-4 throws at one spot | Not a bug. Each carve writes 0 (air) into voxels in its sphere; second carve into the same crater is writing air into voxels that are already air. Log shows the carve completing because the queue drained — the operation is just a no-op when the target voxels are already air. Throw at fresh terrain to confirm. | M5-3D bring-up
