## UE5 port `[ue5]` (active engine — Unreal Engine 5.7, C++)

The Mira-Thal port to Unreal Engine 5.7 (custom source build, C++, Lumen, custom cubic voxel engine at
10 cm). The Godot history above is preserved as heritage on `busy-cannon`. Canonical stack overview:
`design/UE5_TECH_STACK.md`. Build plan + milestone detail: `design/UE5_VOXEL_MESHER_PLAN.md`. The
headless gate is the standalone clang Core harness (`ue5/MiraThal/tests/standalone/build.sh`,
"ALL HARNESSES GREEN").

- **[ue5] M0 — Mesher foundations ✅:** engine-agnostic Core (`mira` namespace, pure C++17, no engine headers) for chunk coords, the greedy mesher, and per-face color. Texturing decided as **per-face solid color** baked into vertex color (NOT a texture atlas) — `base_color(material)` × `face_shade(direction)`, palette in `Core/VoxelColor.h`. Clang harness green.
- **[ue5] M1 — AO/LOD/seams + first render under Lumen ✅:** AO baked into vertex alpha, LOD downsample, chunk seams; `AVoxelChunkActor` renders the greedy mesh via ProceduralMeshComponent (RealtimeMesh swap planned). First voxel chunk rendered under Lumen. **Perf baseline ≈ 6.4 ms GPU on a 7800 XT for an empty Lumen scene.** UE material `M_VoxelTerrain` = VertexColor→BaseColor.
- **[ue5] M2 — Brickmap + generation + carve loop ✅ (built 2026-06-16):** sparse `Brickmap` (8³ bricks) is the single authoritative CPU store; `AVoxelWorld` owns it, generates a region from `HeightmapGenerator`, spawns per-chunk renderers, and runs the dig loop (`CarveAtWorld`/`CarveTestHole` → `BrickmapMeshing` computes edit-affected chunks → re-mesh only those → Chaos collision). Result: multi-chunk generated terrain you can dig into live. **Tooling:** `mcp-unreal` live editor bridge (Remote Control API :30010 + MCPUnreal plugin :8090) is now standard for in-editor spawn/inspect/console/material-authoring/log/viewport checks. Next: **M3** (water + flora + gravity).
